# v2.1 — Polish release design

Date: 2026-10-31 · Status: draft, awaiting approval

## Why

The extension is growing on its own (~250 → ~640 weekly users, Aug–Oct 2026; 276 installs / 67 uninstalls in the last 30 days; 5-star rating). Two things are wrong:

1. **The popup feels crowded, dated and unpolished** (owner's words). It packs four ways to set speed, five settings, a shortcut editor, stats, a feedback form and a large tip box into one 300px column, and every control has the same visual weight.
2. **The tip jar has earned $0, ever.** An always-visible box becomes wallpaper.

Also: the feedback form has received **nothing since v2 shipped** (3 rows total, 2 of them the owner's tests), which suggests it is broken or invisible.

v2.1 is a small, fast release that fixes those things and leaves room for v3 (rename, more streaming sites, paid Pro tier), which comes right after. The owner's goal for money right now is "cover costs / pocket money": earn a little without risking users.

## Goals

- A calm popup that shows only what you touch while watching.
- Speed remembered **per show** by default, so it just works.
- A one-time, milestone-triggered thank-you prompt (tip + Web Store review) replaces the tip boxes.
- Feedback reliably reaches the sheet, and users can find it when something is broken.
- Layout leaves obvious room for a v3 site label/switcher and a Pro badge.

## Non-goals

- No Pro tier, payments, licensing, or ExtPay in v2.1.
- No new streaming sites, no rename, no new branding.
- No change to how speed control or auto-skip work on the page (`content/` logic stays, apart from the per-show default below).

## Anti-goals (would make this a failure even if it "works")

- **Any new permission or host permission in `manifest.json`.** The v2 update's new host permissions likely caused the Aug 26 uninstall spike (Chrome disables the extension until the user re-approves). v2.1 must update silently.
- Losing any existing user's settings, saved speeds, stats or shortcuts.
- Nagging: the thank-you prompt must never show more than once per milestone, and never again after the user tips, rates, or dismisses it permanently.
- Taking away a free feature.

## Look and feel

**Keep the current look**: dark background, Crunchyroll orange accent (owner's decision). "Polish" means consistency, not a new identity:

- Define colors, spacing, radius and type sizes once as CSS custom properties, shared by popup and options (e.g. a small `shared/tokens.css`), and use them everywhere.
- One accent: orange marks the current speed and on-state toggles only. Everything else is neutral.
- Replace emoji used as icons (☕ 🔒 ⏱ 🔥 and the milestone emoji) with simple inline SVG icons. MV3 forbids remote code, so the icons are bundled or inline, not from a CDN.
- Clear hierarchy: one large number (speed), secondary controls quieter, metadata in muted small text.

## Popup

The popup has two states. Both were mocked up and approved in the 2026-10-31 brainstorm.

### Watching state

Shown when the active tab is a supported site **and** the content script reports a video (`getSpeed` → `hasVideo: true`).

Top to bottom:
1. **Show line**: the show's name (prettified series slug, same as `prettifySlug` in `options/options.js`) with the site label underneath (`Crunchyroll` / `HIDIVE`, from `sites.js` `label`), plus a small "Active" status dot on the right. No episode number (we don't have it reliably).
2. **Speed**: a large current-speed number with round − and + buttons on either side. These step by the user's `speedStep` setting.
3. **Presets**: one row, `1x · 1.25 · 1.5 · 1.75 · 2x`. The current one is filled orange. Clicking the current preset does nothing; Reset is done via `1x`.
4. **Per-show line**: "Saved for {Show}" on the left, a "Use for all shows" text button on the right (semantics below).
5. Divider, then an **Auto-skip intros** toggle (the only toggle left in the popup).
6. **Footer**: "{time} saved this week" on the left; stats icon (opens options page) and settings icon (opens options page scrolled to Settings) on the right.

The slider and the separate Reset button are removed.

### Idle state

Shown on any other tab, or on a supported site with no video (e.g. browsing the catalog).

1. Header "Speed controller" with a settings icon.
2. **Stats card**: "Time saved this week" (big number) and "{n} intros skipped · {n}-day streak" underneath.
3. Two small tiles: **All time** saved, and **Top show** (by watch time, from `seriesStats`). Hide the Top show tile if there's no data yet.
4. Auto-skip intros toggle.
5. A muted hint: "Open an episode on Crunchyroll or HIDIVE to change speed".

"This week" means the last 7 days including today, summed from `daily[*].savedSec`. The streak uses the same rule as `computeStreaks` in `options/options.js`; move that function somewhere both pages can share it rather than copying it.

### Milestone thank-you prompt

A one-line card pinned to the bottom of the popup (either state), shown **once** when total time saved first crosses **5h, 25h or 100h** (`stats.totalTimeSavedSec`).

- Text: "You've saved {N} hours" / "Free forever. If it helped, a tip or a review goes a long way."
- Buttons: **Tip** (opens PayPal, `paypalUrl()` with no amount) · **Rate** (opens the Web Store reviews page for this extension, built from `chrome.runtime.id`) · **×** (dismiss).
- *(Claude's call)* A milestone counts as used as soon as its prompt is **displayed**. It stays visible for that popup session (and the next, if the popup was open less than ~2s), then never again. Ignoring it can't turn into nagging.
- *(Claude's call)* **×** dismisses only that milestone; a later milestone can still prompt. That caps it at 3 asks in total. **Tip** or **Rate** ends all future prompts.
- State lives in `chrome.storage.local` (e.g. `milestonePrompt: { shown: [5], done: false }`).
- **Existing users who are already past a threshold**: show the prompt once for the highest milestone they've passed, not one per milestone.

### Tip boxes removed

- The popup's tip box is gone.
- On the options page, the big "Enjoying the extension?" section becomes one quiet line in the footer: "Free and ad-free. Tip the developer" (opens PayPal). `PAYPAL_USERNAME` stays `AkilRajpariLLC`.
- Update the privacy policy only if wording about where the tip button appears needs to change (PayPal is already disclosed).

## Per-show speed (behavior change)

Today `perSeriesSpeed` is **off** by default, so most users never get per-show memory.

New behavior:
- Per-show memory is always on. Changing speed while watching saves it for that show (`seriesSpeeds[slug]`), as long as **Remember speed** is on.
- Opening a show with no saved speed uses the global `speed`, which is the **last speed the user chose anywhere** (owner's decision, 2026-10-31; same as today). Every user-initiated speed change updates both `speed` and this show's entry.
- **"Use for all shows"** clears every per-show override (the global `speed` is already the current speed), so every show plays at this speed until you change it again. A one-line confirmation ("1.5x is now your speed for every show") replaces the per-show line for a few seconds.
- The `perSeriesSpeed` toggle is removed from the UI, and the service worker sets it to `true` on update. *(Claude's call)* The save logic in `setVideoSpeed()` in `content/content.js` changes too (this falls under the per-show exception in Non-goals):
  - Per-show save and restore respect **Remember speed**.
  - Saves happen only on a user-initiated speed change, never when a video merely loads.
  - On Crunchyroll, a per-show speed is saved only once the real series slug has resolved, so episode-slug fallbacks never get written into the 50-show cap.
- Keep the existing 50-show cap on `seriesSpeeds`.
- Remember speed **off** keeps today's behavior: nothing is saved, and every video starts at 1x.

## Options page (stats + settings)

Same page, reorganized and restyled with the shared tokens. Order:

1. Header with streak badge (as today).
2. Stat cards, last-30-days chart, top series, milestones (as today, restyled; emoji → icons).
3. **Settings** section (new), with an anchor (`#settings`) the popup's gear icon opens:
   - Remember speed (toggle)
   - Show speed overlay on video (toggle), currently "Show indicator"
   - Speed step for − / + (0.05 / 0.10 / 0.25)
   - Auto-skip intros (toggle; also in the popup)
4. Keyboard shortcuts (as today; the popup's duplicate shortcut editor is removed).
5. **Send feedback** section (moved from the popup): Bug / Feature / General, a textarea, Submit.
6. Footer: tip line, "Reset all stats".

## Feedback reliability

1. **Check the pipeline first.** `background/service-worker.js` currently reports success on any fetch that doesn't throw, so a broken Apps Script deployment would look like success to the user. Send one test submission and confirm a row appears in the "Crunchyroll Feedback" sheet. If it doesn't, the Apps Script web app needs redeploying, which only the owner can do.
2. Detect failure properly. Apps Script answers HTTP 200 even when the script throws, and returns a sign-in page when access isn't set to "Anyone". So `doPost` should return a success marker (e.g. `{"ok":true}`), and the service worker treats anything else as a failure and shows "Couldn't send. Try again later." This needs the owner to edit the script and redeploy it. *(Claude's call)* Redeploy by editing the **existing** deployment so the `/exec` URL stays the same. If a new URL is unavoidable, update `FEEDBACK_WEBHOOK_URL`; the manifest's wildcard host permissions already cover it.
   *(Claude's call)* **v2.1 doesn't wait on this.** If the redeploy isn't ready, ship with the form moved and `response.ok` checks, and add the marker check in a later patch.
3. **Make it findable when it matters**: if the popup is on a supported watch page but the content script reports no video after a short wait, show a muted "Speed not working? Tell us" link that opens the options page at `#feedback`.
4. Popup feedback copy follows the new voice (no "Please…").

## Data and compatibility

- No changes to the stored keys besides adding `milestonePrompt` (local) and flipping `perSeriesSpeed` to `true` on update. All existing data stays.
- The service worker's `onInstalled` update branch already merges new default keys. Extend it for the `perSeriesSpeed` flip.
- `manifest.json`: version → `2.1.0`. The only other allowed change is adding a shared script file to the `content_scripts` `js` list, which triggers no warning. `permissions` and `host_permissions` stay byte-identical. **No new permissions.**
