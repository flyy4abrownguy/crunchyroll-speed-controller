# v2.1 Polish Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use **superpowers:subagent-driven-development**. The owner chose this method on 2026-10-31; don't ask again. Implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v2.1.0 of the Crunchyroll Speed Controller Chrome extension:
- a calmer two-state popup
- speed remembered per show by default
- a one-time milestone thank-you prompt in place of the tip boxes
- settings and feedback moved to the options page
- feedback failures that are actually detected

All with zero new permissions.

**Architecture:** Plain MV3 extension with no build step.
- All new decision logic goes in one pure, DOM-free file, `shared/logic.js`. It is unit-tested with Node's built-in test runner and loaded everywhere: the popup and options pages via `<script>`, the content script via the manifest, the service worker via `importScripts`.
- Shared look-and-feel tokens go in `shared/tokens.css`.
- UI files are rewritten in place. `content/content.js` changes only its speed-save and apply logic.
- A Playwright + Chrome for Testing smoke suite in `tests/e2e/` drives the real extension against local fixture pages.

**Tech Stack:** Chrome MV3, vanilla JS/HTML/CSS, Node ≥ 22 (`node --test`), Playwright, Chrome for Testing.

**Spec:** `docs/superpowers/specs/2026-10-31-v2.1-polish-design.md`. Read it fully before starting; it has the why, the anti-goals, and the owner's decisions.

## Review Focus

Most likely to bite a real user, each pinned by a test in the owning task:
1. **Video inside a same-origin iframe** (`all_frames: true`). The top frame answers `getSpeed` with no video before the player iframe does, so the popup shows idle mid-episode. Expected: the watching state. (Task 2 responder rule; Task 7 iframe fixture.)
2. **The user changes speed before Crunchyroll renders the series link.** Expected: their choice sticks (a late per-show apply must not override it), and no episode-slug key is written to `seriesSpeeds`. (Task 2; Task 7 delayed-link fixture.)
3. **Tabs opened before the auto-update** have no live content script, so `sendMessage` throws. Expected: the idle popup says "Reload this page to turn on speed controls", not a broken-feedback link, and nothing crashes. (Task 1 `popupMode` tests.)
4. **A supported site but not a watch page** (catalog/home). Expected: the idle state with no "Speed not working?" link. (Task 1 `popupMode`; Task 7 catalog fixture.)
5. **Long-time users already past several milestones** (e.g. 120h). Expected: exactly one prompt (100h), shown once, and it reappears only if the popup closed within 2s. (Task 1 `nextMilestone`; Task 7 milestone flow.)
